# Methods and publication provenance

The [Japanese report](RESULTS.md) documents the statistical plan, service conditions, first-response rule and limitations. The [dataset card](dataset/README.md) documents the generator, conditioning and independent gold verification.

## What was fixed before the main test

- Three primary tests: 120 hard cases per family, 60 English and 60 Japanese. One-sided exact binomial against independent uniform four-choice sampling (p=0.25), Holm across the three families, alpha=0.05. Per-family 95% Wilson intervals are not simultaneous intervals.
- Easy/medium cells, language breakdowns, probability diagnostics and paired variants are secondary diagnostics. Identical-input controls were added after the main test, using the same 60 anchors already fixed for paired variants.
- Gold is generated by code and checked by separate implementations: expression interpreter/SQLite, forward/backward state tracking, and procedural/SQL constraint checking. No model answers are used as gold.
- Correct-letter balance, unique answers, paired semantic equivalence, and candidate uniqueness were checked before sending. The first HTTP 200 per ID and payload hash is scored; a malformed HTTP 200 would count as wrong. Wrong answers do not trigger retries.

The local [original freeze manifest](evidence/original-freeze-manifest.json) records hashes and a pre-test timestamp. It was created before sending the main test and checked again afterward. **This repository was published after evaluation; the manifest is local audit evidence, not an independently timestamped public preregistration.** A [subset manifest](evidence/published-freeze-subset.json) identifies the byte-identical files included here. Paths for omitted files in the original manifest are provenance only, not broken promises of included artifacts.

During pre-API development, a scheduling prototype leaked an advantage to a candidate-only majority heuristic. Candidate plans were changed to symmetric generation before choosing a uniform gold candidate and constructing constraints. v1–v4 were never sent to d1. The evaluated version is v5. Final data verification was performed locally over all 672 items. The generators remain narrow synthetic tests: policy excludes default-only cases, schedule candidates already avoid simultaneous worker clashes, and some cases have no precedence constraints.

## Publication transformation

- The evaluated v5 dataset, generation code, independent oracle, validator and primary statistics code are byte-identical to the local tested files where recorded by the subset manifest.
- Each run publishes a single authoritative `transport.jsonl`. Original runs with only `requests.jsonl` are normalized to that filename. This retains all 853 attempts, not just successful ones. Response payloads, request payloads, timestamps, RTTs, status/error fields and retry metadata are unchanged.
- Local monotonic-clock values, server request IDs and absolute source-file paths are omitted. Historical Jev fixture metadata loses only its local `source_file` field; the request, gold/recorded choice and source index are preserved. No authorization header, credentials or environment file is included.
- `analyze.py` is the reporting portion of the local finalizer, adapted to check only the published frozen subset and to leave the editorial report intact. Statistical/scoring logic is unchanged. The phrase “first valid” in two comments/summary notes was corrected to “first HTTP 200”; those editorially changed source files are not in the byte-identical subset. `verify.py` compares recomputed numeric results with the local final report and verifies all dataset answers with the independent oracle.
- [Original log hashes](evidence/original-log-hashes.json) preserve local-file provenance. Sanitized public files necessarily have different hashes. [Public artifact hashes](evidence/public-artifact-manifest.json) describe this release; generated report timestamps are excluded.
- Full third-party documentation, private conversation/approval records, development drafts, channel graphics/audio and the historical game engine are not redistributed. Source links and the exact decision inputs/results are sufficient to inspect and re-score the reported tests.

The response probability used in confidence diagnostics is `probabilities[choice]`, not the separate API `confidence` field. API `output_tokens=0` is a reported response property, not proof of a particular internal architecture or latency. Language/label variants and exact repeats ran in successive blocks rather than randomized interleaving; their differences cannot be uniquely attributed to language or label order.
